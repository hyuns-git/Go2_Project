# 09. SESSION_00B: Orin2(Orin NX)를 JetPack 6.2.2로 플래시

## 한 줄 요약
Orin2를 Ubuntu 22.04(JetPack 6.2.2)로 다시 설치했다. 호스트 PC 준비, 보드 종류 확인, BSP 설정, 복구 모드 진입, 플래시까지의 절차와 시행착오를 정리한다. 설치 목적은 이 세션에서 따로 설명되지 않았고, 이후 세션(10번)에서 설치 후 설정이 이어진다.

## 먼저 바로잡힌 사실: Orin2의 정체
- 기록에는 "Orin Nano"로 되어 있었지만 실제로는 Orin NX 16GB다. 근거는 RAM 15Gi와 `cat /proc/device-tree/model`의 `NVIDIA Orin NX 16G`.
- 캐리어 보드는 D115W가 아니라 AVerMedia NX215B다. D115W는 확장독 안의 Orin Nano(Orin1) 쪽 캐리어 보드이고, 사용자가 실물을 보고 NX215로 정정했다. 사양서 계열(NX215, NX215B, D115OXB 등)이 같은 문서로 묶여 있다.
- 중간에 Claude가 "잘못된 보드 프로파일로 플래시돼 있어서 이더넷 링크가 안 잡혔던 것일 수 있다"는 가설을 냈다. 확인되지 않은 가설이며 이후 근거도 없다.

## 준비
| 항목 | 내용 |
|---|---|
| 호스트 | 네이티브 x86 Ubuntu가 필요. WSL2는 플래시 위험 때문에 제외. 여분 PC가 Ubuntu 20.04였고, JetPack 6의 SDK Manager가 호스트 20.04를 지원해서 그대로 사용 |
| SDK Manager | 2.4.1 (deb 설치) |
| 부팅 디스크 | Orin2는 NVMe SSD로 부팅 (사용자 확인). 플래시 때 대상은 `nvme0n1p1` |
| 백업 | Orin1의 `ros2_ws`, `go2-nav`, `maps`, `unitree_ros2`, `.bashrc`를 tar로 백업해 호스트 PC로 `scp`. 플래시 전 Orin1 쪽 `~/go2-nav`의 git 미커밋 변경도 정리하라고 안내 |
| BSP | AVerMedia의 JetPack 6.2.2 올인원 패키지 (`AVERMEDIA_JETPACK-R1.4.0.6.2.2_desktop.tar.gz`). 풀면 `JetPack_6.2.2_Linux_JETSON_desktop/Linux_for_Tegra` |

## 절차
1. BSP 압축은 `sudo`로 푼다. (일반 권한으로 풀면 rootfs 소유권이 어긋난다.)
2. `Linux_for_Tegra`에서 `sudo ./setup.sh`:
   - 캐리어 보드: `0) D115` (이 선택이 NX215B. `nv-d115*.dtb` 안에 `nx215` 문자열이 있는 것으로 확인)
   - 모드: `0) Normal Mode` (Super Mode는 Orin Nano 8G/4G 전용이라 Orin NX 16G에는 해당 없음)
   - MIPI 카메라 프로파일: `0) no camera`
3. 계정 생성: `sudo ./create_user.sh` (sudo 필요). 기존 백업 경로가 모두 `/home/nvidia/...` 기준이라 기본 계정명 `nvidia`를 유지했다.
   - `ERROR: please install qemu-user-static`: 호스트가 x86인데 arm64 rootfs 안에서 명령을 실행해야 해서 필요한 패키지. 설치 후 해결. 플래시 전 사전요구사항 스크립트로 `abootimg`, `device-tree-compiler`, `nfs-kernel-server`, `sshpass` 등 빠진 패키지도 설치했다.
4. 복구 모드(Force Recovery) 진입:
   - 수동: Orin2 전원 OFF → RECOVERY 버튼(SW4) 누른 채 전원 ON → 약 2초 후 버튼 해제
   - 케이블: 이 보드는 USB Type-C가 아니라 Micro-B USB 2.0 포트가 복구용. Micro USB 케이블이 없어서 처음에 막혔다.
   - 확인: 호스트에서 `lsusb | grep -i nvidia`에 NVIDIA 장치(ID `0955:7323`)가 보여야 한다. 안 보이면 `install.sh`를 돌리지 않는다.
   - 버튼이 안 먹힐 때의 방법: 부팅된 Orin2에서 `sudo reboot --force forced-recovery`. 이 명령은 재부팅이 아니라 "다음 부팅은 복구 모드"라는 플래그를 걸고 전원을 끈다. 이 보드는 SW2 자동 전원 켜짐이 기본 OFF라서 꺼진 뒤 Power 버튼(SW3)을 직접 눌러야 켜진다. 처음에는 꺼진 뒤 안 켜져서 고장으로 오해했지만 정상 동작이었다.
5. `sudo ./install.sh` → 대상 선택에서 `0) nvme0n1p1` (`sda1`은 다른 USB 저장장치). 10~20분 소요. 진행 중 케이블과 전원은 건드리지 않는다.
6. 플래시 후: 네트워크 인터페이스(기가비트 포트 2개 인식), JetPack 버전, USB 장치를 확인하고, 복구용 USB를 빼고 정상 부팅.

## 시행착오
- 보드를 D115W로 오인해서 D115W 매뉴얼(복구 포트 안내 등) 기준으로 안내가 나갔다가 NX215B 매뉴얼 기준으로 정정됨.
- `create_user.sh`를 `sudo` 없이 실행해 `Please use root to decompress this BSP.` 오류.
- 안내문의 `<원본_tar.gz_파일명>`은 자리표시자였는데 그대로 실행하는 바람에 풀어 둔 폴더까지 `rm -rf`로 지워서 BSP를 다시 풀었다. 자리표시자는 반드시 실제 값으로 바꿔서 실행해야 한다.
- 호스트 PC의 호스트명을 Orin2와 같은 `nvidia-desktop`으로 바꾸는 명령이 실행됐다. 같은 이름의 기기가 네트워크에 둘이 되므로 호스트 쪽을 원래 이름으로 되돌리거나 Orin2 이름을 달리하라고 안내했다.
- 플래시 전에 Orin1을 백업하는 이유를 사용자가 되물었다. 이유는 Orin2에 쌓인 설정이 아니라 Orin1 쪽 스택(맵, 노드 코드)이 되돌아갈 지점이기 때문이다.

## 확인이 필요한 항목
- 이 재설치의 목적(왜 22.04로 올렸는지)은 이 세션에 없다.
- 플래시 직후 검증 결과(포트 2개 인식 등)는 이 세션 끝에 확인 요청까지만 있고 결과 기록이 없다. 10번 세션으로 이어진다.
- 호스트 PC 호스트명 변경 문제의 최종 처리 여부.
