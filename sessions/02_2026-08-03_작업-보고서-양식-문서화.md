# 02. 지금까지 한 일을 보고서 양식에 맞춰 문서화

## 한 줄 요약
7월 말까지 Go2에서 구현한 것(환경 설정, 기본 동작, LiDAR 시각화, SLAM 지도 저장)을 회사 보고서 양식(.docx)으로 항목별로 만들었다. 기술 작업보다 문서 생성 자동화가 중심인 세션이고, 사용자가 붙여 넣은 7월 작업 기록에는 이후 가이드에 쓸 사실이 많아서 따로 정리해 둔다.

## 문서 구성 (최종 4개 항목)
1. item1 개발환경 구축 (ROS 설치, SDK 설치, 네트워크, 노드와 토픽 확인)
2. item2 기본 동작 제어 (터미널에서 앉기, 일어서기)
3. item3 LiDAR 시각화 (RViz2)
4. item4 SLAM 지도 생성과 저장 (원래 4~6으로 나눴다가 서로 의존성이 높아 하나로 합침)

만드는 방식: Node.js `docx` 라이브러리로 `build.js`, `items.js`, `generate.js`를 만들어 양식(제목, 날짜와 작성자 표, 요약 표, 터미널 명령 정리, 증빙 사진, 실행 예시, 비고 상자)을 코드로 재현했다. 사용자가 item1, 2를 직접 손봐서 사진과 날짜를 넣은 뒤에는 덮어쓰지 않도록 item3, 4만 다시 만드는 `generate_34.js`를 따로 두었다.

여러 번 수정한 부분:
- 터미널 명령은 목록 안의 목록 대신 `명령어 | 설명` 두 열 표로, 코드 블록은 회색 배경
- 비고는 파란 상자, 각 터미널 제목 아래에 왜 이 명령을 쓰는지 설명 추가
- 읽는 사람이 로봇을 잘 모른다는 전제로, 개념(LiDAR, PointCloud, frame_id가 왜 맞아야 하는지), 데이터를 고른 이유, 성공 기준을 항목마다 넣음
- 양식이 중간에 바뀌어서 요약 표의 "구분" 열을 좁히고 인터페이스 이름(eth0), 주소 값을 갱신

## 사용자가 붙여 넣은 7월 작업 기록에서 확인되는 사실
LiDAR 시각화 절차(사용자 정리):
1. `ros2 topic list`로 `/utlidar/cloud` 확인
2. `ros2 run rviz2 rviz2` 실행
3. 왼쪽 아래 Add, By topic에서 `/utlidar/cloud` 안의 PointCloud2 선택
4. Fixed Frame을 `utlidar_lidar`로 설정, Topic은 반드시 `/utlidar/cloud`
5. Decay Time으로 몇 초 분량의 점을 남길지 조절

SLAM 매핑 파이프라인 (7월 31일 버전):
`/utlidar/cloud_deskewed` (PointCloud2, frame_id `odom`) → `pointcloud_to_laserscan` → `/scan` → `slam_toolbox` → `/map`

| 확인 항목 | 기록된 값 |
|---|---|
| `/scan` 주기 | 처음 11~13Hz로 측정되다가 오래 재면 약 14.9Hz로 안정. `cloud_base` 단독 변환 테스트는 약 15.45Hz |
| `/map` 주기 | 0.5Hz (설정상 2초에 한 번, 정상) |
| `/utlidar/cloud_base` | frame_id `base_link`, 변환이 단순해서 변환 테스트용으로 좋음 |
| `/utlidar/cloud_deskewed` | frame_id `odom`, 이동 중 스캔 왜곡이 보정돼서 최종 SLAM 입력으로 채택. 문제는 deskewed 자체가 아니라 TF 타임스탬프 불일치였음 |

그때 만난 오류와 해결 (사용자 기록 그대로 요약):
| 오류 | 원인 | 해결 |
|---|---|---|
| GitHub `Invalid username or token`, 비밀번호 인증 미지원 | 비밀번호 인증 폐지 | `git clone` 대신 codeload tarball 사용 |
| `gzip: not in gzip format` | 내려받은 파일이 404 안내 문구였음 | 저장소와 브랜치를 정확히 쓰고 `curl -f` 옵션 사용 |
| `Package 'pointcloud_to_laserscan' not found` | 환경을 source하지 않음 | `unitree_ros2/setup.sh`, `ros2_ws/install/setup.bash`를 source |
| Foxy에서 `--once` 불가 | Foxy 미지원 | `timeout 3 ros2 topic echo 토픽 \| head -n 15` |
| `Message Filter dropping message: frame 'odom'` | PointCloud 타임스탬프와 `odom → base_link` TF 타임스탬프가 다름 | `odom_tf.py`에서 `stamp = now.to_msg()`를 `stamp = msg.header.stamp`로 수정 |
| 시작 직후 `Invalid frame ID "odom"`, `"map"` | TF가 아직 안 나온 짧은 구간 | 이후 값이 계속 나오면 정상, 끝까지 안 나오면 실제 문제 |
| `slam_toolbox` exit code -11 | 전체 launch를 Ctrl+C로 종료하는 과정에서 1회 발생 | 매핑 중 상시 발생이 아니면 종료 순서 문제로 봄. 반복되면 추가 조사 필요 |

재현 절차 (터미널 3개): 1번 `ros2 launch go2_nav_bridge mapping.launch.py`, 2번 `ros2 topic hz /scan`, `ros2 topic hz /map`, `tf2_echo odom base_link`, `tf2_echo map odom`으로 상태 확인(`/scan` 약 15Hz, `/map` 약 0.5Hz), 3번 `rviz2`(Fixed Frame `map`, Map, LaserScan, TF 추가).
저장: `map_saver_cli -f ~/maps/my_map` 후 `slam_toolbox/srv/SerializePoseGraph`로 `.posegraph`, `.data`도 저장.

## 메모
- 이 세션의 매핑은 01번 세션에서 `scan_maker`로 교체되기 전의 방식이다. 01번에서 실측한 결과(더미 점 86.5%, 시계 오프셋 49.13초)가 이 방식이 왜 한계였는지를 설명한다.
- 문서 증빙으로 넣을 자료로 `colcon build` 성공 로그, `ros2 topic list` 출력(`/sportmodestate`, `/lowstate`, `/wirelesscontroller`, `/api/sport/request`, `/utlidar/cloud`) 등이 제안됐다.
