# 07. Orin Nano 무선랜: 부팅 자동연결, 절전 끄기, watchdog, ping 로거

## 한 줄 요약
USB 무선 어댑터를 쓰는 Orin Nano가 재부팅 후 Wi-Fi를 못 잡는 문제에서 시작해, 건물 전체(AP 여러 대, 같은 SSID)에서 쓸 수 있게 5가지 설정을 적용했다. 이어서 게이트웨이로 ping을 계속 보내 지연을 기록하는 로거를 만들고 Orin2(`nvidia-desktop`)에도 같은 설정을 옮겼다. 여기서 만든 watchdog은 나중에 오히려 연결을 끊는 원인으로 지목된다(42, 43번 세션).

## 문제
1. 재부팅 후 Wi-Fi가 자동 연결되지 않아 HDMI로 화면을 연결해 수동 재설정해야 했다. 어댑터는 TP-Link T4U Plus(RTL8812AU 계열 칩셋)이고, USB 어댑터라 부팅 초반 NetworkManager 스캔이 끝난 뒤에야 드라이버가 올라올 수 있다.
2. 건물이 층마다 여러 AP가 같은 SSID로 운영되는 구조라서, 층을 이동할 때 AP 사이 로밍이 안정적이어야 한다. 리눅스와 일반 USB 어댑터 조합은 기본적으로 로밍에 소극적이라 신호가 거의 끊길 때까지 기존 AP를 붙잡는 경우가 많다.

## 적용한 설정 5가지와 이유
| # | 설정 | 방법 | 이유 |
|---|---|---|---|
| 1 | 자동연결 + 최우선순위 | `nmcli connection modify <프로필> connection.autoconnect yes`, `connection.autoconnect-priority 100`, `connection.autoconnect-retries 0` | 다른 Wi-Fi 프로필이 여럿 등록돼 있어서 엉뚱한 곳에 붙거나 재시도 횟수 제한으로 자동연결이 실패하는 것을 막음 |
| 2 | 부팅 후 강제 재연결 | `/etc/systemd/system/wifi-reconnect.service`: `sleep 20` 후 `nmcli connection up <프로필>`, `systemctl enable` | 어댑터 인식이 NM 스캔보다 늦는 경우를 보완. `enable`만 하고 재부팅하지 않으면 로그가 없는 것이 정상. 상태가 `disabled`로 나오면 `enable`이 안 된 것 |
| 3 | 절전(power save) 끄기 | `nmcli connection modify <프로필> 802-11-wireless.powersave 2`, `/etc/NetworkManager/conf.d/wifi-powersave-off.conf`에 `[connection]`, `wifi.powersave = 2` | 절전이 켜지면 무선 칩이 주기적으로 잠들어 명령 지연과 패킷 손실이 생김. 실시간 로봇 명령에는 치명적 |
| 4 | MAC 랜덤화 끄기 | `/etc/NetworkManager/conf.d/wifi-scan.conf`에 `[device]`, `wifi.scan-rand-mac-address=no` | 멀티 AP 구조에서 MAC이 바뀌면 AP 쪽이 매번 새 기기로 보고 재인증이 늦어질 수 있음 |
| 5 | watchdog | `/usr/local/bin/wifi-watchdog.sh`: 기본 게이트웨이로 `ping -c 2 -W 3` 실패 시 `nmcli connection down`, 2초 뒤 `up`. `cron`으로 1분마다 실행 | 로밍 실패나 일시 끊김 때 사람이 없어도 자동 복구되게 함 |

## 적용하지 않은 것과 검토가 필요하다고 남긴 것
- 5GHz 또는 2.4GHz 밴드 강제 고정: 실측 후 결정
- 공유기에서 MAC 기반 고정 IP(DHCP reservation): 관리자 권한 필요
- AP의 802.11k/v/r(빠른 로밍) 지원 여부: 네트워크 담당자 확인 필요, 로밍 안정성에 가장 큰 영향을 줄 항목
- 층별 이동하며 실측 로밍 테스트: 미실시

## ping 로거
- 게이트웨이(공유기)로 ping을 계속 보내고 지연을 로그에 쌓는 셸 스크립트를 만들고, `ping-logger.service`(systemd)로 부팅 시 자동 시작되게 했다.
- 막혔던 곳
  - `status=203/EXEC`: 실행 파일이 없거나 실행 권한이 없을 때 나는 오류. 파일을 옮기거나 다시 만드는 사이의 타이밍으로 보였고 이후 `active (running)`이 됨
  - 부팅 직후 네트워크가 올라오기 전에 ping이 실패해서 스크립트가 바로 종료됨
  - 유닛 파일 파싱 오류: `StartLimitIntervalSec`가 `[Service]`에 들어가 있었음. `[Unit]` 섹션으로 옮겨야 하고, `Requires=wifi-reconnect.service`는 빼고 `After`만 남김
  - 로그 줄이 전부 `INFO`로 분류됨: ping 출력이 한글 로케일(`시간=`)이라 패턴이 안 맞았음. `LC_ALL=C ping ...`으로 로케일을 고정하는 수정이 필요
  - `ping-logger`를 재시작하면 MobaXterm 연결이 불안정해지는 것 같다는 관찰이 있었음(원인은 확정되지 않음)

## Orin2(`nvidia-desktop`)로 옮기기
- 스크립트에 로그 경로가 `/home/unitree`로 하드코딩돼 있어서 계정이 `nvidia`인 Orin2에서는 `mkdir: 허가 거부`로 실패. 경로를 홈 기준으로 고쳐서 해결.
- `sed -i`로 한 줄을 고치다가 `LC_ALL=ping`처럼 줄이 깨지는 사고가 났다. 이후 안내는 `sudo bash -c 'cat > 파일 << EOF'`로 파일을 통째로 쓰는 방식으로 바꿨다. 여러 줄 설정은 `sed`보다 파일을 통째로 쓰는 편이 안전하다.
- Orin1과 같은 설정이 적용됐는지 항목별로 `nmcli connection show ... | grep -E "autoconnect|priority"` 등으로 대조해서 1~5번이 동일하게 적용된 것을 확인.
- 세션 후반에 Orin2를 Ubuntu 22.04로 재설치해서 설정이 모두 사라졌고, 빠짐없이 다시 설정하는 체크리스트를 요청했다. 이 체크리스트에는 이 세션에서 검증한 1~6번과, 이전 세션 기억에 있는 내부망(eth1) 설정이 들어갔다. 후자는 이 대화에서 검증한 것이 아니라서 재설치 직전 연결 이름을 다시 확인하라고 안내했다.

## 확인이 필요한 항목
- watchdog 스크립트는 연결이 "끊김"과 "연결 중"을 구분하지 않아서, 이후 세션(42번)에서 진행 중인 연결을 강제로 끊는 문제로 이어졌다. 여기서는 "가이드에 그대로 옮기지 말 것"으로 표시한다.
- MAC 랜덤화를 끄면 로밍이 좋아진다는 설명은 일반론이며 이 프로젝트에서 효과를 측정한 기록은 없다.
